# 问答

被问过、或者我们自己问过自己的问题。答案尽量短，细节都在链接里。

## 关于内容本身

### 为什么同一个功能有两个实现？

不是为了比较语言优劣，是因为**验证需要独立实现**：

- [fyserver](/projects/fyserver)（C#）与 [kards-server-go](/projects/kards-server-go)（Go）：
  两个实现对着同一份抓包各自还原协议，能一致的地方才敢写进[私服教程](/private-server/)；
  不一致的地方往往正好是「协议里我们还没搞懂的那部分」。
- [UAssetRegistry](/projects/uassetregistry) 与 [solstice-bin](/projects/solstice-bin) / [solstice-assetregistry](/projects/solstice-assetregistry)：
  前者是通用库、走语义级回写；后者走「不动就逐字节不变、只在末尾追加」。
  目标不同，容错方式也不同。

### 为什么不直接改引擎源码 / 用官方工具？

引擎源码解决不了 cooked 资产的问题：游戏里跑的资产已经序列化完了，编辑器那套加载路径不适用。
另外版本漂移是常态——一份源码对不上某个 build 的魔改，结论就废了。
所以我们更依赖「从字节出发 + 用实测反推」。

### 为什么每个库都只验证一个 UE 版本？

因为**验证需要真实数据**，而真实数据来自具体某个游戏版本。没验证过的版本我们不会写成
「支持」——写「只验证过 UE 5.6」不是谦虚，是准确的描述。

### 为什么文档里这么多「未验证」「推断」？

因为我们宁可让人误以为我们不自信，也不想让人误以为工具已经稳了。
站内的[写作与取证约定](/lab/conventions)把「实测 / 推断 / 未验证」三档写清楚了。

## 关于使用

### 我能直接拿这些去改线上游戏吗？

技术上很多工具做得到，但那不是这些项目的目的：

- 私服工作面向**自建环境**，客户端与服务端都在你手里；
- 修改在线服务端或在线对局可能违反游戏的 ToS / EULA，也可能导致封号；
- [faction-mobile-so](/projects/faction-mobile-so) 与 KMod 的仓库里都明确写了免责声明。

### 为什么仓库里没有游戏文件、密钥或 SDK dump？

版权与许可。游戏资产、APK、AES 密钥、Dumper-7 导出的 SDK 头都不属于我们能再分发的东西。
所有仓库都按「你自备合法来源的输入」来写，README 里会说明需要哪几样。

### 为什么 Prism 编译不起来？

它的 [README](/projects/prism) 里写得很直接：`external/CUE4Parse` 不在仓库里，`.gitmodules`
也拉不到匹配的树（开发时用的是带本地改动、早于当前上游的快照）。你需要自己提供一份匹配的树，
或者用上游 `main` 然后接受 API 漂移。另外 Android 侧还需要 `third_party/lib/` 下的几个 `.so`。

### 为什么解包出来的贴图在手机上花屏？

大概率是你把 PC 的像素格式直接搬过去了。cooked 资产的像素格式写在 `.uasset` 头里，
头决定了 mip 数据落在哪，替换只能覆盖数据、改不了头。
[Prism 的跨平台移植](/projects/prism)就是干这个的：解码来源像素 → 重新编码成**母 pak** 的格式。

### 为什么我改完蓝图，游戏里没生效 / 直接崩？

按最常见的原因排序：

1. **改的是存根，不是 ubergraph。** 事件函数通常只是存根，真正的逻辑在 `ExecuteUbergraph_<Class>`
   的某个 case 里（[蓝图逆向 · 罕见之处](/ue5-bp/05-pitfalls)）。
2. **跳转偏移没重排。** 跳转操作数是**字节偏移**，节点长度一变就必须全部重算。
3. **`KismetPropertyPointer` 用了旧形态。** UE5.6 必须用 `New`（`FFieldPath`）形态。
4. **改了名字表却没重算哈希。** name batch 的 CityHash64 必须与 UE 逐位一致。
5. **文件写坏了而你没读回。** 所以我们的写回工具都强制读回 + 其余函数字节比对。

### 想跑 AI 对局，选 KardsSim 还是 kards-client-headless？

- 要**规则尽量贴近真实游戏**：[KardsSim](/projects/kardsim)——它直接执行从真实蓝图直译出来的 C#。
- 要**轻量、快、方便改卡做实验**：[kards-client-headless](/projects/kards-client-headless)——
  Rust 规则核心 + Lua/C# 写卡，但只覆盖已实现的卡包，且与原版客户端的完整对战未验证。

## 关于团队

### 可以加入吗？怎么贡献？

没有正式流程。最实际的方式是在具体仓库提一个有内容的 Issue 或 PR——勘误、复现记录、
一个新版本的兼容性报告都算。参见[团队介绍 · 参与与联系](/about/#参与与联系)。

### 为什么不公开成员名单的全部？

因为很多人只做验证与内部工作，没有公开的提交记录；把名字列出来却对应不上工作，反而误导。
表里只列有公开可见工作的人，且明确标注不代表完整名单。

### 站内的数字（Star、推送时间）为什么不实时？

项目总览里的仓库表是 `npm run sync` 跑出来的快照，不是实时数据。
具体见[维护本页](/projects/#维护本页)。

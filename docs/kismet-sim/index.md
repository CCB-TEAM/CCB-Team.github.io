# Kismet 直译模拟器：设计与心得

这套东西的起因很简单：**想要一个本地对局模拟器来训练 AI**，
而 KARDS 的卡牌逻辑全在客户端蓝图里，只有游戏本体能跑。

于是有两条路：读卡面文字猜效果，或者把蓝图逻辑搬出来。
第一条路试过，放弃了；第二条路做通了。

这一组文章记的是第二条路上的**设计决策、踩过的坑、以及事后看当初哪里想错了**。

## 一句话结论

::: tip 如果只记一句
**这套系统里最危险的不是崩溃，是"编译通过、跑得动、数字是错的"。**
所有真正的 bug 都是静默的，所以能失败的断言比能跑通的程序重要得多。
:::

## 数字

| 指标 | 值 |
|---|---|
| 直译产物 | 1671 个资产 · 6254 个函数 · 42.5 万行 · 18.7 MB |
| 手工代码 | 37 个 `.cs` 文件（运行时 + hook 缝 + 引擎 + 审计工具） |
| 引擎原语 | 138 个（直接改 `GameState` 的叶子函数） |
| 触发点 | 68 个枚举值，卡牌实际注册 61 个，引擎全部会发 |
| 自对弈 | 4.9 ms/局，500 局 0 异常 / 0% 未实现调用 |

对比一下工作量分布：**1671 个资产是机器转译的，138 个原语是手写的**。
把"要手写多少"从 226 个函数压到 138 个叶子原语，是这套架构的全部价值。
